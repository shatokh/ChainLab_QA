# Architecture

ChainLab QA is a local-first Web3 QA Automation playground. The current architecture is intentionally small, inspectable, and optimized for repeatable local verification.

## Current Stack

- Frontend: Next.js with TypeScript.
- UI modules: Wallet Connect, Test Token Faucet, NFT Mint, and DAO Voting panels.
- Local domain logic: TypeScript helpers under `lib/`.
- Smart contracts: Solidity contracts under `contracts/`.
- Contract tests: Hardhat Solidity tests.
- Browser E2E: Playwright with a mocked local wallet provider.
- CI evidence: GitHub Actions local verification workflow.
- Local reports: static HTML evidence report generated by `corepack yarn evidence:local`.

## Local-first Network Model

Local Hardhat behavior is the default Web3 verification model. Automated checks must not require public RPC, testnet credentials, real funds, production wallets, paid services, or mainnet access.

The browser E2E layer uses mocked-provider flows to validate wallet-facing UI behavior without requiring a real wallet extension. Solidity tests validate contract behavior locally.

## Verification Flow

```text
spec
  -> failing or updated test where applicable
  -> implementation
  -> local verification
  -> evidence docs
  -> AI Change Record
  -> diff review against spec
```

Primary commands:

```bash
corepack yarn verify
corepack yarn test:e2e
corepack yarn evidence:local
```

`corepack yarn verify` runs type generation, TypeScript checks, linting, node tests, local Solidity tests, and formatting checks.

## CI/CD

GitHub Actions runs local verification, installs Playwright Chromium, runs mocked-provider E2E, generates local evidence, and uploads a local evidence artifact.

This artifact is local evidence only. It does not prove public testnet, mainnet, live wallet extension, hosted app, or production behavior.

## Optional Testnet Strategy

Public testnet deployment is deferred to optional Phase 10. If reconsidered later, it must use:

- one selected public testnet;
- a separate test-only wallet;
- free faucet funds only;
- configurable public or free-tier RPC;
- no committed secrets;
- evidence clearly separated from local evidence.

Mainnet remains prohibited.

## Security And Configuration

- `.env.example` may document placeholders only.
- Real `.env` files are ignored.
- Private keys, seed phrases, mnemonics, API keys, wallet exports, and RPC tokens must never be committed.
- Paid services must not become required without a future approved spec.

## Known Limits

- Local Hardhat success is not public network validation.
- Mocked-provider E2E is not live wallet extension validation.
- Optional testnet readiness is not an actual deployment.
- No production deployment or mainnet validation is planned.
